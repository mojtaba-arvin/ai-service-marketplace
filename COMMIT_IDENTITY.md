# Commit identity and attribution policy

This policy applies to human contributors, owner-authorized AI-assisted work, and repository automation.

## Maintainer-directed AI-assisted work

For implementation work explicitly authorized and owned by the maintainer, use this Git author identity:

- Name: `Mojtaba Arvin`
- Email: `m.arvin@live.com`

Use it only after confirming that this exact email is verified on the maintainer's GitHub account. GitHub attribution depends on the email being associated with the account; a configured name/email alone does not prove account ownership.

Do not use model, assistant, AI-agent, Copilot, Claude, Cursor, Codex, Gemini, generic agent, or bot names/emails as the author of maintainer-directed implementation commits. Do not add bot/AI `Co-authored-by` trailers to those commits.

When a PR contains maintainer-directed AI-assisted work, include this exact marker in its body so the repository check can enforce the maintainer identity:

`<!-- maintainer-directed-ai-work -->`

Disclose AI assistance in the PR description using the repository's normal disclosure conventions. The marker is a machine-readable policy signal, not a claim that the maintainer personally typed every line.

## Human contributors

Never rewrite, relabel, or replace a real human contributor's author name/email with the maintainer's identity. Preserve each contributor's genuine authorship, including external contributors. Do not amend or rewrite historical commits merely to normalize their metadata.

## Genuine automation

Automation must remain distinguishable from human work. GitHub Actions, Dependabot, release bots, and other automation may author a commit only when the commit is genuinely generated by that automation and the PR is explicitly labeled `allow-automation-commits`. This is a narrow exception, not a way to attribute agent-written implementation to a bot. Do not add bot co-author trailers, even under this exception.

A GitHub `web-flow` committer is not the same as a bot author. The author identifies contribution attribution; the committer identifies who recorded the Git object. Evaluate these fields separately.

## Local Git defaults

These are convenience defaults for maintainer-directed work, not an enforcement boundary:

```sh
git config --global user.name "Mojtaba Arvin"
git config --global user.email "m.arvin@live.com"
```

Repository-local configuration, environment variables, API-created commits, and workflow code can override these defaults. The pull-request check is the enforcement layer.

## Enforcement

`scripts/check_commit_identity.py` validates every commit in a pull request:
- Rejects bot/agent authors and bot/AI co-author trailers.
- Allows known automation authors only when the PR has the explicit `allow-automation-commits` label.
- For PRs containing the `maintainer-directed-ai-work` marker, requires every commit author to be exactly `Mojtaba Arvin <m.arvin@live.com>`.
- Preserves other human authors without relabeling them.

This repository's AGENTS.md prohibits implementers from modifying `.github/**`, so this PR deliberately does not install a GitHub Actions workflow. Until the repository owner authorizes that governance exception, run the validator manually before requesting review or merge:

```sh
python3 scripts/check_commit_identity.py \
  --repository mojtaba-arvin/ai-service-marketplace \\
  --pr-number <PR_NUMBER>
```

This manual check is not a server-enforced merge gate. Do not mark the Issue complete or merge until the check has been run and its result recorded. Never bypass existing required checks or reviews.

## Important limitation

Git commit metadata is self-asserted. This check can reject known bot/agent identities and enforce the declared maintainer identity marker, but it cannot prove that a person physically typed the code or detect every disguised agent identity. The GitHub account/email association and transparent PR disclosure remain important.
